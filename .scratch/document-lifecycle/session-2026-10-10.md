## "Front-end can't access endpoints" — diagnosed

Backend, ngrok and CORS were fine. Two separate problems on the partner's side:

1. **Mock auth token.** ngrok inspector (`localhost:4040`) showed his calls
   (`/admin/dashboard`, `/users/`, user agent `node` = Next.js server-side)
   arriving with `Authorization: Bearer mock-token:mock-document-issuer`. The
   backend only accepts Supabase JWTs → `401 Invalid authentication token`
   (`jwt.invalid.token: Not enough segments`). Fix: turn off the front-end's
   mock login, sign in with Supabase (same project as the backend) and send
   `session.access_token`.
2. **DNS on his phone.** `DNS_PROBE_FINISHED_NXDOMAIN` for the ngrok host. It
   resolves on Google, Cloudflare, Quad9 and AdGuard DNS — his network/ISP DNS
   blocks `*.ngrok-free.app`. Fix: Android Private DNS `dns.google`, switch
   Wi-Fi ↔ mobile data, or DNS 8.8.8.8 / 1.1.1.1.

Also checked:

  HTML warning page with 200).

  browser origin (e.g. a Vercel deploy) gets 400 → add it to `CORS_ORIGINS`
  and recreate `backend`. Server-side (Node) calls aren't subject to CORS.

## Infrastructure / providers — design vs code

Design (`docs/architecture.md` → **Providers**, line ~323):

- Each infrastructure folder: `base.py` (Protocol + I/O models),
  `<name>_*.py` adapters, `factory.py` with `build_*()` choosing from settings.
- `infrastructure/providers.py` is the **only** place features get adapters
  from, and refuses to start when `ENVIRONMENT=production` with any
  memory/mock adapter selected (1.0 shipped prod on mock chain + email).
- Features wire, never choose: `get_intake(db) → DocumentIntake(db, store=providers.document_store())`.
- Seams: objects (supabase, memory) · drafts (google_docs, memory) · queue
  (celery, inline) · ocr (mineru, pypdf, tesseract, memory) · llm (openrouter,
  memory) · embeddings (sbert, memory) · chunking (markdown, spacy) · chain
  (web3, memory) · email (resend, memory).
- Live documents and archived originals = **two `ObjectStore` instances (two
  buckets)**, not two modules.

Gap in this repo:
- No `objects/` seam — storage is `clients/supabase_storage.py` with no
  Protocol; backup is its own `backup/` module instead of a second bucket.
- No `providers.py`, no production guard → `get_blockchain_provider()` still
  gives production the mock chain.
- `blockchain/` and `queue/` have adapters but no factory; email's builder
  lives in `email/__init__.py`.
- Already in shape: `drafts/`, `google/`, `nlp/*`, `backup/`.
